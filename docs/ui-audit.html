OpenFlow vs NayaFlow

A page-by-page comparison of the open-source OpenFlow client against NayaFlow v1.25.1 — run before calling the UI “close enough for now.” Every gap below is something NayaFlow does that OpenFlow doesn’t yet, ranked by how much it matters.

Verdict

The core editor is at or above parity — Bindings, Color, Layers, Profiles and all eight Settings tabs match or exceed NayaFlow. Both High-priority items are now fixed (Modules is editable and the 1-finger Touch gestures are back), along with two Low ones. What remains is the Hardware Manager (firmware / pairing) — the Phase-3 work blocked on a firmware image — plus device-gated and polish items. Nothing here blocks day-to-day keymapping.

Intentional divergences

not gaps

Places OpenFlow deliberately differs — call these out so they don’t get “fixed” back toward NayaFlow by mistake.

Divergence

Color is its own page

WhyNayaFlow toggles LED mode inside the keymap view via the 💡 tab; OpenFlow promotes Color to a top-level page (your call). Tools — brush/fill/pipette, palette + hue/sat/hex creator, solid/swirl/breathe/spectrum — are at parity.
Divergence

Flat text sidebar (8 items) vs icon rail (5)

WhyNayaFlow nests Color & Macros inside the keymap and uses a 5-icon rail; OpenFlow’s labelled sidebar is flatter and more discoverable.
Divergence

Hub landing / status page

WhyOpenFlow opens on a Hub (backend + device status); NayaFlow opens straight into the keymap.
Divergence

No Save / “Unsaved changes” / flash button

WhyOpenFlow auto-saves to a local SQLite DB and works fully offline; NayaFlow’s Save flashes the device (that’s Phase 3 here).

Method. Compared live OpenFlow (localhost) against live NayaFlow v1.25.1 for Bindings, Module Configuration and Hardware Manager, plus the full NayaFlow screenshot library (all 8 Settings tabs, Color / RGB selector, module bind & settings screens, keybind-selector tabs) and the recovered NayaFlow routes.

Caveats. NayaFlow’s Macros page doesn’t exist to compare against, and a couple of NayaFlow sub-views weren’t driven live — those gaps are inferred from the route map + screenshots and are flagged as such.
